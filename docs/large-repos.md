# Large Repository Guidance

Stringer works out of the box on most repositories, but repos with 10k+ files
benefit from a few configuration tweaks.

## Collector Timeouts

By default collectors run to completion with no timeout. On very large repos
the duplication, todos, deadcode, and patterns collectors can take several
minutes. Set a per-collector timeout to keep scans predictable:

```bash
stringer scan . --collector-timeout=60s
```

Or configure it in `.stringer.yaml`:

```yaml
collector_timeout: 60s
```

When a collector exceeds the timeout it is cancelled and its partial results
are discarded. The scan continues with the remaining collectors.

## Duplication Collector

The duplication collector caps file input at 10,000 files and output at 200
signals (configurable via `max_issues`). On a stress-test scan of a mixed
monorepo the uncapped collector produced 7,554 signals — the cap keeps output
actionable.

```yaml
collectors:
  duplication:
    max_issues: 100   # tighter cap if needed
```

## Recommended Excludes

Stringer ships with default excludes that every collector honours:

- **Vendored trees**: `vendor/`, `node_modules/`, `third_party/`, `3rdparty/`,
  `extern/`, `external/`, `bower_components/`, `wwwroot/lib/`, `testdata/`,
  `eval/`, `.beads/`, `.stringer/`, `.claude/worktrees/`
- **Precompiled and minified bundles**: `**/compiled/**`, `**/*.min.js`,
  `**/*.min.css`, `**/*.bundle.js`, `**/*.production.js`,
  `**/*.development.js`
- **Generated source**: `**/zz_generated*.go`, `**/*.pb.go`, `**/*_string.go`,
  `**/*.generated.*`, `**/*.g.cs`, `**/*.Designer.cs`

On top of the globs, source-walking collectors (complexity, duplication,
deadcode, coupling, todos, patterns, githygiene) skip any file whose first five
lines contain a generated-code marker (`Code generated`, `DO NOT EDIT`,
`@generated`, `<auto-generated`) and any file whose average line length over
its first 20 lines exceeds 400 characters (minified). In the September 2026
benchmark these rules removed ~50% of the signals reported for `vercel/next.js`
(all under `packages/next/src/compiled/`) and ~21% for `kubernetes/kubernetes`
(`zz_generated.*.go`, `*.pb.go`).

Add project-specific excludes for generated code or large vendored trees, and
prefix a default with `!` to opt back in:

```yaml
exclude_patterns:
  - "generated/**"
  - "assets/**"
  - "!**/*.pb.go"     # scan protobuf output after all
```

`--include` patterns bypass the content-based generated/minified check for the
todos collector but not the default globs; use `!` to lift a glob.
